# Plan 16: Markdown Editor Parity

## Goal

Make the rich HTML editor feel like Obsidian Markdown reading/live-preview content while keeping the OneNote-style Libre shell. The editor must adapt cleanly to light and dark themes, use a darker Microsoft Word-like caret in light mode, invert text and surface colors in dark mode, keep an 8px editor margin, and make special Markdown constructs look and behave like their Obsidian Markdown counterparts.

## Cross-Cutting Rules

- Keep visual styling token-only and aligned with `DESIGN.md`.
- Prefer Obsidian-rendered DOM classes and data attributes already preserved by `markdown-sync`.
- Do not make protected content editable unless the preservation model explicitly supports it.
- Keep source export conservative: preserve exact source when unchanged; infer Markdown only when the edited DOM has enough information.
- Use React Testing Library for behavior, snapshots for component rendering, and computed CSS assertions for theme, caret, margin, and fold controls.
- Verify live behavior through Obsidian MCP after each implementation plan.

## Done When

- Every explicit behavior in the matrix has either been implemented or intentionally deferred in a later numbered plan.
- Light and dark themes have readable editor surfaces, inverted text colors, and visible caret colors.
- Task checkboxes, callout folding, links, tags, footnotes, and collapse controls behave like Obsidian Markdown content.
- Markdown mirror sync preserves the Obsidian source contract for edited and unedited constructs.
- All local checks and Obsidian MCP verification pass.
